FIX #1: ENSEMBLE CONFIDENCE PASS-THROUGH
================================================================================

FILE: src/ml/exit_policy_ensemble.py
METHOD: get_optimal_allocation()

CHANGE LOCATION: ~Line 139-141 (return statement modified)

KEY CHANGE:

FIX #2: WEIGHTED ACCURACY CALCULATION
================================================================================

FILE: src/analysis/signal_combiner.py
METHOD: combine_signals()

FORMULA:
  Final_Confidence = (Raw_ML_Confidence * 0.7) + (ML_Accuracy * 0.3)

CHANGE LOCATION: ~Line 223-260 (NEWS_GUARD_WEIGHTED section)

KEY CHANGES:
  1. Initialize tracking variable:
     weighted_admission_score = None
  
  2. Extract ML_ACCURACY from technical signals:
     ml_accuracies = []
     for s in (synchronized_signals["technical"] or []):
         acc = float(getattr(s, "indicators", {}).get("ML_ACCURACY", 0.0) or 0.0)
         if acc > 0:
             ml_accuracies.append(acc)
  
  3. Apply weighted formula:
     if ml_accuracies:
         avg_accuracy = sum(ml_accuracies) / len(ml_accuracies)
         weighted_ml_conf = (float(raw_ml_conf or 0.0) * 0.7) + (avg_accuracy * 0.3)
  
  4. Use weighted if improved or NEWS_GUARD active:
     if weighted_ml_conf > float(raw_ml_conf or 0.0) or self.news_guard_active:
         normalized_ml_conf = weighted_ml_conf
         weighted_admission_score = weighted_ml_conf
         self.override_ml_confidence = normalized_ml_conf
  
  5. Store for downstream:
     self._normalized_ml_conf_for_cycle = float(normalized_ml_conf or 0.0)

EXAMPLE (USD/JPY):
  0.39 * 0.7 = 0.273
  0.60 * 0.3 = 0.180
  Total     = 0.453 ✓

VERIFICATION:
  ✅ Coefficients 0.7 and 0.3 present in calculation
  ✅ Formula: (raw * 0.7) + (accuracy * 0.3)
  ✅ Normalized value stored and flowed downstream
  ✅ USD/JPY example produces 0.453

FAQ
================================================================================

Q: Will this break existing high-confidence signals?
A: No. The max() function ensures any confidence >= 0.10 is preserved.
   High-confidence signals benefit, low-confidence signals still filtered.

Q: What if a signal has 0.39 confidence but no accuracy data?
A: The FIX #2 won't apply weighting (no accuracy available).
   FIX #1 still applies: max(0.10, 0.39) = 0.39 passed through.
   Result: Signal still improves from 0.10 → 0.39 (FIX #1 helps).

Q: Does this affect position sizing?
A: Yes, but positively. Higher confidence → potentially larger positions.
   This is desired (more confident signals get more capital).
   Capped at reasonable bounds (0.25-2.0x multiplier).

Q: What if the NewsGuard floor is very high (0.50)?
A: Weighted accuracy helps: (0.39 * 0.7) + (0.60 * 0.3) = 0.453
   Still might not pass 0.50 floor, but much closer than 0.10.
   Signal gets best possible score thanks to fixed formula.

Q: Can I disable the weighted accuracy formula?
A: It's always applied if accuracy data exists (FIX #2 design).
   This is intentional (weighting is beneficial).
   To revert, rollback both files or remove FIX #2 changes manually.

Q: How do I know if weighted formula is working?
A: Look for [NEWS_GUARD_WEIGHTED] and [WEIGHTED_ADMISSION] in logs.
   Also check [ENSEMBLE] confidence values vs [FILTER_REJECT] decisions.

Q: Should risk settings change after deployment?
A: No. Risk settings (NEWS_GUARD floor, min confidence) unchanged.
   Only HOW signals are calculated improved (not gates/floors).
