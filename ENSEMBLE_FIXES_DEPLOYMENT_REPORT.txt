FORMULA:
    Final_Confidence = (ML_Confidence * 0.7) + (ML_Accuracy * 0.3)

EXAMPLE WALKTHROUGH (USD/JPY):
  Input: Raw Confidence = 0.39, ML Accuracy = 0.60
  Step 1: 0.39 * 0.7 = 0.273
  Step 2: 0.60 * 0.3 = 0.180
  Step 3: 0.273 + 0.180 = 0.453 ✓ (matches requirement)
  Result: 0.453 > 0.20 (NEWS_GUARD floor) → ADMITTED ✓

IMPLEMENTATION DETAILS:
  • Always extracts ML_ACCURACY from technical signals
  • Calculates weighted score regardless of NEWS_GUARD state
  • Applies weighting if: weighted > raw OR NEWS_GUARD is active
  • Updates override_ml_confidence with weighted value for downstream flow
  • NEW: Stores _normalized_ml_conf_for_cycle for explicit tracking

LOGIC FLOW:
  1. Extract raw_ml_conf from override_ml_confidence
  2. Try to extract ML_ACCURACY from technical signals
  3. Calculate: weighted_ml_conf = (raw * 0.7) + (accuracy * 0.3)
  4. Use weighted if: weighted > raw OR news_guard_active
  5. Store normalized value for downstream admission controller
  6. Pass through ensemble as base_confidence (triggers FIX #1)

TECHNICAL DEEP DIVE

WHY max() INSTEAD OF REPLACEMENT?

The max() function ensures:
  1. SAFETY: Never goes below 0.10 (minimum floor)
  2. PRIORITIZATION: Uses higher of ensemble or ML confidence
  3. FLEXIBILITY: Works in all market regimes
  4. NO SIDE EFFECTS: Only affects confidence, nothing else

Example cases:
  • Ensemble: 0.10, ML: 0.39  → max(0.10, 0.39) = 0.39 ✅ (use ML)
  • Ensemble: 0.50, ML: 0.30  → max(0.50, 0.30) = 0.50 ✅ (use ensemble)
  • Ensemble: 0.15, ML: 0.15  → max(0.15, 0.15) = 0.15 ✅ (same)

WHY WEIGHTED FORMULA (0.7, 0.3)?

The coefficients reflect:
  • 0.7 weight on Raw ML Confidence: Current signal strength (more important)
  • 0.3 weight on ML Accuracy: Historical reliability (secondary confirmation)

Intuition:
  • A model saying "I'm 39% sure" (raw) is important
  • A model saying "I'm 60% accurate historically" (accuracy) confirms reliability
  • Combined: (39% * 0.7) + (60% * 0.3) = 45.3% weighted confidence
  • Result: Higher confidence than raw 39%, but lower than pure 60%
  • Sweet spot: Balances current signal with model trustworthiness

WHY [WEIGHTED_ADMISSION] INSTEAD OF WARNING?

The old "Attempting signal preservation" was:
  • Passive voice ("attempting")
  • Defensive tone (suggesting failure)
  • Low severity (WARNING)

The new "[WEIGHTED_ADMISSION]" is:
  • Active voice ("Signal promoted")
  • Confident tone (successful decision)
  • Normal severity (INFO)
  • Includes explicit reasoning and scores

This better reflects that weighted admissions are GOOD, not a fallback.
